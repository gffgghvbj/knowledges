# 第二阶段：知识库问答实施计划

依据：已确认的 interview-knowledge-design.md；用户已授权开始第二阶段，在线服务选择 DeepSeek。沿用现有独立功能分支，主代理连续实施，最后一次独立代码审查。

## 设计与边界

- DeepSeek（默认地址 https://api.deepseek.com，可编辑模型名）、OpenAI 兼容服务和 Ollama。主进程请求，系统 safeStorage 加密密钥，不导出密钥与模型设置。
- 本地中文分词及段落检索，无需额外付费向量服务；范围包括全部、网站、栏目及主题关键词。当前版本自动建立索引，历史回答保留不可变版本、原文行号和摘录。
- 单次问题为持久记录；先落库再调用模型。失败、取消、重启保留问题，重试创建新记录。生成答案按段落关联有效引用，资料不足与模型补充分开展示。
- 备份升级为 v2，兼容导入 v1；问答按 ID 合并，冲突保留双方，不自动恢复网络请求。
- 本阶段不实现模拟面试或简历处理。

## Task 1: 索引、持久记录与检索

先写失败测试：中文自然问题检索、范围、更新/恢复仅命中当前版本、历史引用仍可读取。实现 SQLite 加法迁移、段落索引与记录接口。运行 knowledge 测试及 typecheck。

## Task 2: 模型设置与问答服务

先写失败测试：本地 HTTP 服务验证两种协议、无效引用拒绝、超时/失败落库、密钥隔离。实现受限地址配置、加密设置、可取消模型请求与结构化回答校验。

## Task 3: 备份与前端

先写失败测试：v1 导入、v2 问答往返及冲突幂等合并、引用关系校验。实现模型设置、知识库问答页面、历史及原文引用面板。添加端到端流程。

## Task 4: 验证与交付

运行 typecheck、全部单测、Electron 端到端测试；独立审查，修复重要问题并回归。生成 macOS/Windows v0.2 构建，记录真实平台验证边界。

## Review Focus

检查模型服务地址及密钥泄漏、跨版本引用真实性、导入内容与引用验证、取消/重启竞争条件、无密钥与空资料用户体验、旧版数据升级。禁止将测试服务通过等同于真实 DeepSeek 推理验证。
