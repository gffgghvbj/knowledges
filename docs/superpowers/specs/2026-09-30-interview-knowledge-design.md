# 本地面试知识库桌面应用：需求设计

日期：2026-09-30

状态：分阶段功能设计已在对话中确认；本文件待整体审阅。尚未开始技术选型、实现计划或代码开发。

## 1. 目标与使用对象

为个人面试准备提供一款支持 macOS 和 Windows 的桌面应用。将散落在网站上的学习资料收集为本地 Markdown，基于资料问答，并结合题库、个人简历和目标职位描述（JD）进行文字模拟面试与评分。

不需要多人账号或登录系统。网站自身的登录与应用账号是不同概念：采集受限资料时仍需用户登录来源网站。

资料原文不由用户直接编辑。个人笔记、问答、练习记录与采集原文分开管理，避免更新覆盖个人内容。独立笔记编辑器不列入当前交付范围。

## 2. 已确认的边界

- 同一个桌面应用分三阶段交付：资料库、知识库问答、面试练习。
- 支持整站发现与采集学习资料；扫描后可选择栏目，默认选择全部学习资料。
- 首批适配小林 coding 和 JavaGuide。整站指所选网站范围内的学习正文，不递归采集外部链接，也不将导航、广告、评论作为文章保存。
- 支持公开内容和用户登录后有权访问的内容。用户手动登录、扫码或完成验证码，程序沿用登录状态采集；不以绕过访问限制为功能目标。
- 用户手动触发网站更新，不做定时后台检查。
- 原文与图片保存到本地，问答及面试支持在线 API 和本地模型。
- 第一版面试采用文字，不含语音面试。
- 跨设备采用单文件备份包导出、导入和合并，不包含实时云同步。

首批样例：

- https://xiaolincoding.com/interview/redis.html
- https://www.javaguide.cn/java/jvm/jvm-garbage-collection.html

## 3. 阶段一：资料库

### 使用流程

1. 添加网站入口，扫描站内学习资料链接。
2. 展示栏目、文章数量及扫描状态，允许取消不需要的栏目。未完成扫描时明确标记数量并非完整总量。
3. 必要时在应用内由用户登录网站。
4. 开始采集，展示进度与每篇文章的结果，支持暂停、继续、失败重试。
5. 按网站和栏目阅读、搜索本地资料，打开对应的本地文件或来源网页。
6. 用户点击更新后检查新增及变化的文章。

### 保存与更新

- 保存正文标题、层级、代码块、表格和图片；图片引用指向本地资源，便于离线阅读。
- 记录文章稳定标识、来源 URL、网站、栏目、标题、采集时间和内容版本。
- 重复发现同一文章不生成多个独立副本；URL 规范化及站点特例在适配时定义。
- 正文或相关资源变化产生新版本，旧版本保留并可恢复。无内容变化时不重复生成内容版本。
- 源站文章移除时标记来源状态，保留本地副本。一次超时、登录失效或访问失败不等同于源站删除。
- 登录失效时暂停受影响任务，重新登录后继续；单篇失败不应丢失已成功采集的内容。
- 存储失败时不得将文章标记为采集成功，保留可重试状态。

### 单文件备份与合并

- 导出一个包含清单、资料、图片、历史版本及已交付模块业务数据的备份包。
- 后续阶段增加题库、简历、JD、问答记录、面试记录和评分的导出，不改变单文件使用方式。
- 网站登录状态和 API Key 默认不导出，另一台电脑单独配置。
- 导入采用合并去重，保留双方新增数据；重复导入同一备份不重复创建记录。
- 同一文章内容不同时，默认以采集时间较新的版本作为当前版本，旧版本保留且可恢复。这是用户选择的合并规则，并不代表采集时间能证明源站内容更正确。
- 同一文章时间相同而内容不同的边界情况：拟保留双方版本，维持目标设备当前版本，并在导入结果提示冲突，不静默丢弃内容。
- 面试、问答等记录按稳定唯一标识合并；不同记录即使文本相同也分别保留。
- 导入前检查格式、版本兼容性及资源完整性；损坏或不支持的备份给出明确错误，不破坏已有资料。备份中的路径不可写出资料目录。
- 导入结果显示新增、更新、重复、冲突及失败数量。

### 验收标准

- macOS 和 Windows 均可完成添加网站、扫描、采集、阅读、搜索、手动更新及导出导入。
- 两个首批网站的代表性文章可保留关键正文结构、代码、表格和本地图片；离线可阅读已完整保存的文章。
- 登录采集通过实际需要登录的目标内容验证；若指定样例无登录要求，不能用公开页面冒充登录能力验证。
- 暂停、重启或失败重试后可继续任务，已采集文章不重复入库。
- 更新后的文章可查看历史并恢复；来源不可访问时本地副本仍存在。
- 两台设备互相导入后保留各自新增数据，重复导入不增加重复记录，冲突遵循既定版本规则。

## 4. 阶段二：知识库问答

### 使用流程与回答要求

- 在全部资料或指定网站、栏目、专题范围内提问。
- 系统检索本地资料，将相关片段交给所选模型组织答案。
- 答案引用具体文章及对应段落，可打开本地原文或来源网页。
- 资料不足时明确说明；模型补充的知识与有本地资料支持的内容分别标注。
- 引用关联实际使用的文章版本，后续更新不能使历史回答的依据悄然变化。
- 问答记录本地保存，纳入备份合并。

### 模型与检索

- 可配置、验证和切换在线 API 或本地模型。具体协议、服务商及本地运行工具在技术设计阶段选定，不承诺所有模型接口通用。
- 使用在线服务时，相关资料片段、问题或面试回答按需发给用户选择的服务；本地保存不等同于所有计算均在本地进行。
- 资料新增、更新、恢复版本或导入后，自动更新检索索引并显示处理状态；未完成处理的资料不声称已可完整检索。
- 索引是可重建的派生数据。跨设备导入后自动重建或校验，不依赖原设备的绝对路径。
- 模型不可用时保留问题和记录，允许重试或切换模型；本地阅读和资料管理仍可使用。

### 验收标准

- 能切换在线模型和本地模型完成问答。
- 限定资料范围后，引用来自该范围内的实际段落。
- 对资料未覆盖的问题明确指出不足，不伪造引用。
- 更新或恢复文章后新问答使用当前有效内容，历史引用仍可追溯。

## 5. 阶段三：面试练习

### 题目与输入资料

- 文章与题目分开管理。题目关联知识点、参考答案及来源文章版本。
- 区分原文整理的题目与 AI 生成的题目或补充答案。
- 简历和 JD 均支持直接粘贴文字、导入 PDF、导入 Word，导入后展示提取结果并允许修正。
- Word 的具体扩展名兼容范围、扫描型 PDF 是否需要 OCR，在技术设计中明确；解析失败必须提示，不将空白或乱码作为有效输入。

### 面试配置与过程

- 范围支持专题练习和目标岗位综合面试。
- 岗位综合面试可结合用户简历、JD 和本地知识库：简历引导项目与职责追问，JD 决定考查重点，知识库提供技术依据。
- 配置难度、总题量及出题模式。
- 题库模式从已有题目中随机抽取；AI 延伸模式允许生成新题、场景题和基于回答的追问。
- 题库模式单场内尽量无重复；题量超过可用题目数时明确提示并允许调整，不静默补入 AI 新题。
- 每次展示一道题，用户文字作答。追问计入总题量，不无限延伸。
- 练习模式逐题展示解析与评分；正式模拟在整场结束后统一展示，中途不泄露参考答案和评分。
- 回答和面试进度及时保存。模型调用失败后可重试，不要求用户重新输入已保存的回答。

### 评分与复盘

- 技术题评估正确性、完整性和表达清晰度。
- 项目题评估职责说明、技术取舍、解决问题的过程和回答的一致性，不将知识库答案当作个人项目经历的事实判定标准。
- 每个分数给出具体理由、遗漏或错误及改进建议；依据不足时明确标注。评分作为练习反馈，不保证等同真实招聘评价。
- 评分量表、权重和提示词应有版本，记录本次使用的模型及评分规则，以便理解不同场次的结果。
- 保存题目、回答、追问、评分及整体报告，整理薄弱知识点并关联本地复习资料。

### 验收标准

- 专题和岗位范围可与两种出题模式、两种反馈时机组合使用。
- 简历和 JD 三种输入方式均能完成提取、确认及用于出题的流程。
- 岗位面试能体现简历项目和 JD 要求，而非仅随机抽取通用知识题。
- 追问受总题量限制，正式模拟中途不展示解析。
- 分数附有针对实际回答的理由，资料不足时不伪造确定性结论。
- 面试记录可在重启后查看，并随备份合并导入另一台设备。

## 6. 模块边界与数据流

以下是逻辑边界，不指定编程语言、框架、数据库或部署方案。

1. 桌面界面：管理来源、任务、阅读、问答、面试与设置。
2. 采集模块：站内发现、站点适配、登录会话、任务进度与重试。
3. 资料模块：Markdown、图片、元信息、文章版本及原文阅读。
4. 备份模块：备份包清单、校验、稳定标识和合并规则。
5. 检索与模型模块：资料索引、引用定位、在线及本地模型连接。
6. 面试模块：题库、简历与 JD、面试状态、评分和复盘。

主要数据流：网站 → 采集与正文提取 → Markdown 与资源、文章版本 → 检索索引及题库 → 问答或面试 → 本地历史记录。

简历与 JD 经提取和用户确认后进入面试模块。备份模块覆盖持久化业务数据，派生索引可重建。Markdown 应可脱离应用阅读，不成为仅能由应用解释的封闭格式。

## 7. 后续技术设计与验证

以下事项是实现前的技术决策，不属于已被用户批准的技术方案：

- 桌面框架、采集引擎、存储与检索方案，以及两平台打包方式。
- 应用内登录会话是否能被采集引擎可靠复用；验证过程中需要真实网站状态及用户完成登录。
- 首批网站正文选择、栏目发现、重复 URL、图片及动态内容的处理。
- 在线模型协议、本地模型连接方式及用于检索的模型配置。
- Word 格式、扫描 PDF 支持边界和导入失败处理。
- 资料规模、磁盘占用及采集速度的代表性验证；在验证前不承诺全站耗时或任意规模性能。
- 备份兼容版本、同时间冲突的提示体验，以及评分量表的具体定义。

用户审阅本文件后，再细化技术方案和实施计划。当前不安装依赖、不创建外部服务、不开始代码实现。
