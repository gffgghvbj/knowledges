# 向量检索与精排设计

用户要求在现有知识库问答增加向量检索，指定在线 Embedding 为 `qwen3.7-text-embedding-flash`，rerank 为 `qwen3.7-text-rerank`，回答继续使用已配置的 DeepSeek 或本地聊天模型。沿用个人使用、macOS/Windows、本地数据、离线阅读、版本引用及便携备份。

## 方案

使用本地 SQLite 持久化归一化向量，余弦精确检索与现有关键词召回各取 24 条，用 RRF（k=60）融合，最多 24 条交给 rerank，最终最多 8 条、18000 字符交给回答模型。暂不引入独立向量服务器或 ANN 原生依赖，减少跨平台部署负担；个人库规模增加后可替换检索后端。

向量模型和聊天模型独立设置。Embedding 支持 DashScope 原生、兼容 embeddings 接口和 Ollama；rerank 支持 DashScope 原生及兼容 rerank 接口，可关闭。接口使用完整 URL，避免拼接错误。默认模型采用用户指定名称，默认维度 1024；具体业务空间 URL 和 Key 在应用中填写。模型测试仅发送内置短文本。

## 索引生命周期

- 复用带文章版本和行号的现有片段；向量与输入内容哈希、模型/地址/协议/维度指纹绑定。不同模型空间不得混用。
- 批量最多 8 条、约 24000 字符；参数和返回数量、索引、维度、数值严格校验，向量归一化后保存。
- 首次需点击「建立 / 继续索引」；该操作启用后台增量维护。新增、更新、恢复及导入会自动补齐；暂停、失败、重启行为持久化。失败停止请求，明确显示原因，用户可继续。
- 设置变化立即暂停并取消旧请求；旧请求返回不得污染新模型索引。写入前检查片段仍属于当前版本及内容一致。
- 超过回答上下文容量的单个片段不进入向量索引，展示排除数量，正文仍可读。
- 向量是可重建派生数据，不放入便携备份；跨设备导入检测缺失后按本机已启用的索引任务补齐。API Key 和模型配置均不随备份迁移。

## 问答与可观察性

先保存问题，再异步生成查询向量、检索与精排。模型超时/取消仍保留问题。查询失败降级关键词并显式标注；rerank 失败使用融合顺序并显式标注；取消不得被当作降级继续发请求。只有当前范围、当前版本、相同模型指纹和维度的向量参与召回。精排索引必须对应本次候选，拒绝重复/越界/非有限分值。

记录本次实际检索方式、Embedding/rerank 名称及降级说明，纳入现有问答备份。引用仍验证历史原文，不导出向量或密钥。

## 界面

模型设置增加独立的「向量检索与精排」区域，包含协议、完整地址、模型、维度、密钥、开关及测试按钮。索引区显示已完成/待处理/排除数量、状态、错误、继续/暂停/重建操作。明确在线索引会发送资料片段、在线精排会发送问题和候选段落；使用本机模型则发往本机服务。

## 验收

通过可控制 HTTP 服务验证无关键词重合的语义召回、精排顺序、协议格式、范围隔离、更新/恢复/导入、缓存复用、模型切换、过期请求、暂停取消、断线及维度异常。保留全部旧测试，补桌面设置与完整问答流程，独立审查后生成 macOS/Windows 新版包。无真实 Key 时不声称实际模型推理质量已验证。
