# 实施决定与审查记录

基线提交 `8c14a8c`。用户选择在当前会话由主代理逐项实现；整分支只做一次独立只读审查。

## 实施决定

1. 在原本没有代码或 Git 仓库的目录创建 `feat/local-library`，不另建工作树。没有现有主分支需要保护；将来整合其他分支时可能需要独立工作树。
2. SQLite 使用 Node 内置 `node:sqlite`，替代计划中的 better-sqlite3，避免 Electron 与 Windows 原生模块 ABI 重建。代价是需要 Node 24+ 和兼容 Electron；桌面测试已验证当前 Electron 44.5.0 可用。
3. 不单独为每篇文章维护文件写入 journal；不可变历史文件先落盘，再以数据库当前版本为恢复依据，启动时重建 current.md。代价是启动 IO 随文章数量增长。
4. 重启后的中断任务保持暂停，用户手动继续，避免无提示启动网络请求。代价是崩溃恢复后多一次点击。
5. 每来源使用一个串行采集工作器，代替计划中的两个并发工作器，降低恢复状态复杂度与网站负载。代价是整站采集较慢。
6. 站点选择规则集中在一个适配模块，更新复用采集队列。没有创建只做转发的独立文件；后续规则增长时可拆分。
7. 按实际运行时限制，手动跟踪同源重定向，并使用标准 referrer 选项下载图片。跨域规范化跳转不会静默扩大采集范围，可能需要用户用最终地址重新添加来源。
8. 仓库是新建本地仓库，没有已有主分支或远端。保留功能分支，不执行合并或推送。

## 独立审查及修复

审查范围：`8c14a8c..3c674201ad165697604904e11f11a6a703d034c9`。以下问题均增加复现测试、观察失败、修复后通过：

- 备份允许未引用文件堵塞资料目录：清单文件集合现在必须恰好等于版本正文和关联图片。
- 扫描重试丢失发现阶段：重试扫描会恢复发现模式，继续发现失败页面的子链接。
- HTTP 200 二维码/订阅门槛被误作正文：增加明确登录/订阅门槛识别，避免替换已有内容。该识别是防误保存措施，不承诺适配全部网站登录方案。
- 更新不检查失去导航入口的已保存文章：更新种子包含所选范围内的已有文章 URL，404 仅标记移除，保留原文。
- Retry-After 处理被列为轻微问题，但其行为违背限流等待要求，提升为本次修复：支持秒数与 HTTP 日期，不将 120 秒缩短为 60 秒，并通过可中断短等待实现。

作者集成测试另发现并修复暂停后立即继续的竞争条件、Electron URL 与跨源图片请求差异。
