# v0.9.1 云同步漏传修复

日期：2026-10-08。

## 根因与修复

原实现即使没有完整向量，也把文章版本写入 chunkVersions。后来建好索引，版本没有变化，因而始终跳过。新版使用当前模型 fingerprint 查询，校验每个适用分块的 input_hash 与向量存在性，缺少任何一项则不清理远端、不记录完成。成功上传后按文章保存版本、模型和完整数据的摘要；重建向量或恢复历史版本均能触发更新。重传之前清除旧摘要，避免失败后的旧完成记录阻止修复。

原 sync-state.json 对所有目标复用。新版格式 v2 包含云端地址与密钥的组合摘要；目标变化或旧格式均重新建立同步记录，保守重传图片与向量。尾部斜杠规范化，摘要不含明文密钥。不修改远端协议，不更改资料库数据库格式或备份格式。

界面显示同步分块数和待补传文章数。旧版同步记录首次升级不复用，可能重新上传已有数据。

## 验证

- 首次复现测试：6 项中 5 项按预期失败，覆盖未完成索引、切换地址、切换密钥、旧标记迁移和模型变化；修复后通过。
- 补充测试复现重传失败后旧摘要导致恢复漏传，修复后通过。
- 9 项同步单元测试使用真实临时 SQLite 资料库，网络边界用模拟响应，不调用真实云端。
- `npm run typecheck` 通过；`npm test`：30 个文件，105 项通过。
- 新增桌面测试通过本地 HTTP 服务验证缺少向量提示、补齐后上传，以及更换目标后的重传；打包版原有 14 项桌面回归通过；新增同步测试首次因夹具错误写到 userData 根目录而失败，修正为实际 library 子目录后通过（1.0 秒）。共 15 项桌面用例验证通过。

## 产物与限制

`release/v0.9.1` 包含 macOS ARM64 应用、Windows x64 ZIP 及 SHA256SUMS.txt。macOS 未发行签名/公证；Windows 未实机运行。测试不使用用户密钥或真实云服务，云端服务兼容性仍需实际环境验证。
