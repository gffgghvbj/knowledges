# v0.5.1 列表与输入性能优化

日期：2026-10-01。范围：现有布局下优化列表读取、刷新、输入保存，不改变题目、评分规则、数据库 schema 5 或备份格式 v4。

## 改动与原因

- 问答、面试、题库和简历/JD 列表改为 SQL 摘要投影，不再把完整回答、参考答案、简历和场次快照批量传到页面；选中记录后按 ID 读取详情。面试详情仍通过正式模式投影隐藏答案。
- 列表摘要一次加载，页面每次最多渲染 50 条；题库文章选择器同样分页。问答全选明确作用于本页，翻页清除选择，防止误删未展示的记录。
- 问答/面试仅在存在生成任务时轮询，详情仅刷新当前运行记录。全局仅在采集或索引运行时轮询；其他操作后请求增量状态，没有变化时不回传列表。后台有进展时不再重复传输未改变的文章/来源。
- SQLite 连接内临时触发器记录表修改版本，索引统计按版本缓存；索引完成且资料未变化时不再重复遍历和哈希全部片段。修改资料、导入、重建和配置变化仍会使缓存失效。临时对象不写入数据库持久结构或备份。
- 输入框自身管理热状态，避免面试每输入一个字就重新渲染历史。题库筛选、栏目整理和 Markdown 阅读增加缓存；资料搜索在中文输入法组合期间不发起查询。
- 草稿内容仍立即送入主进程，主进程在连续输入停顿 400ms 后合并写入 SQLite，避免逐字解析和重写整场记录。离开输入框、切换页面、读取详情、提交、提前结束、备份和正常关闭时处理待存草稿；删除/提交后丢弃过期缓冲，避免迟到写入覆盖。

## 测量与验证

使用合成数据，未读取或发送用户简历、API Key 或个人资料。

| 场景 | 原路径 | 优化路径 |
|---|---:|---:|
| 200 场面试列表序列化传输体积 | 5,735,801 字节 | 32,001 字节 |
| 同一测试中列表读取与投影耗时（单次样本） | 26ms | 10ms |
| 400ms 内连续 100 次草稿编辑产生的保存调用 | 100 | 1 |
| 页面题目数量（120 条测试数据） | 全量渲染 | 50 / 50 / 20 |

耗时为本机合成样本，非所有数据规模的保证；列表传输量减少约 99.4%。尚未对用户真实资料库做帧率或输入延迟测量，也没有将摘要列表改为服务器游标分页，特别巨大的记录集合仍有进一步优化空间。

- `npm run typecheck`：通过。
- `npm test`：24 个测试文件、73 项通过。
- `npm run test:e2e`：开发版与最终 macOS ARM64 包各 10 项桌面回归通过，包括采集、历史分类、向量问答、PDF/DOCX、题库和正式模拟。
- 新桌面回归使用 120 道长题目，核对分页和筛选；使用 Chromium IME 组合/提交事件验证中文输入；切换页面及接受最后一次草稿 IPC 后立即关闭原生窗口，重启验证末尾文字保留。
- 新单元回归覆盖保存合并、磁盘写失败后的重试、删除/提交丢弃缓冲、摘要不含完整快照、事务回滚不改变修改版本，以及索引完成后不再重复扫描而新增资料仍触发更新。

## 使用与边界

两端 asar 版本核对为 0.5.1，document worker、CMap 和对应平台 canvas 原生依赖齐全；Windows ZIP 已校验全部条目并生成 SHA-256。

使用 `release/v0.5.1` 中的新应用，先退出旧版本。数据格式保持兼容，不需要重新导入资料或重建索引。macOS 包仍未签名/公证；Windows x64 包需要解压全部内容后运行，尚未在 Windows 实机验证。

主进程缓冲只保障正常导航、提交与关闭；强制杀进程、断电可能丢失尚未落盘的末尾草稿。磁盘写入失败时保留缓冲，显式保存和关闭会报错，不把失败当作成功。
