# 第三阶段验收 · 拾知 v0.5.0

验收日期：2026-09-30。交付范围为简历/JD、题库、文字模拟面试与备份迁移。

## 使用路径

「面试资料」导入或粘贴文字，预览修正后保存；「题库」录题或从文章生成候选并确认；「模拟面试」选择专题/岗位、题库/AI、练习/正式模式。岗位模式必须选择简历和 JD。默认 5 题，支持 1–20 题，追问计入总量。

作答草稿自动保存；回答先保存再评分。失败与应用重启均需要手动重试，不自动重发。练习模式逐题反馈，正式模式结束或确认提前结束后才显示评分。历史快照不受原简历、JD 或题库删除影响。

技术题按正确性 50%、完整性 30%、表达 20% 计算；项目题按职责 25%、取舍 30%、过程 30%、一致性 15% 计算。规则版本为 `interview-v1`。平均分只取已评分题；报告显示已答、计划和未评分数量。

## 验证证据

- `npm run typecheck`：通过。
- `npm test`：22 个文件、68 项测试通过。
- `npm run test:e2e`：开发版和最终 macOS ARM64 包各 9 项桌面测试通过，包括中文 PDF/DOCX 导入、既有采集、登录复用、知识问答、分类删除、向量精排回归。
- 文档测试覆盖文本型 PDF、依赖 CMap 的中文 PDF、DOCX、空文档、损坏文件、文件/文本上限、解析超时、压缩展开超限、伪造解压长度、加密 ZIP 条目拒绝。
- 面试测试覆盖 8 种模式组合、非法分数/引用、重复提交、失败重试、结束/删除后迟到结果、启动恢复和正式模式 IPC 投影。
- 暂停页面轮询后切换面试记录，草稿仍保留；关闭应用再启动仍可继续。
- 备份覆盖完整场次往返、删除原资料后的快照、同 ID 冲突、重复导入幂等、旧 v3 导入与非法数据拒绝。

独立代码审查发现两项重要问题，均经失败回归复现后修复：DOCX 现在逐条流式读取并核对实际解压大小，避免只相信 ZIP 目录声明；草稿使用每场每题的即时缓存，避免切换记录时被旧轮询结果覆盖。另补齐题库类型筛选，修复 PDF 中文 CMap/字体资源本地路径。没有待处理的审查问题。

## 打包与平台

产物位于 `release/v0.5.0`，旧版本保留。两端 asar 均已核对为 0.5.0，均包含 document worker、中文 CMap 与对应平台 canvas 原生二进制。Windows ZIP 已校验全部条目并生成 `SHA256SUMS.txt`。macOS ARM64 为未签名、未公证的本地应用；Windows x64 为解压运行包，没有 Windows 实机验收，不能据打包成功推断运行兼容性。发布前需在实际 Windows 上验证导入、密钥保存与面试流程。

PDF 解析依赖 `pdfjs-dist@6.3.289` 和平台对应的 `@napi-rs/canvas@1.0.9` 原生依赖，worker、CMap 与字体资源随包交付。在 macOS 跨平台打包 Windows 时，额外使用 npm 官方 tarball 的 `@napi-rs/canvas-win32-x64-msvc@1.0.9`；先放入对应 node_modules 目录，再构建并核对 unpacked 原生文件。Windows 本机 `npm ci` 会按平台安装该可选依赖。

## 数据和限制

数据库升级为 schema 5，备份格式为 v4，兼容导入 v1/v2/v3。两台设备均应升级 v0.5；旧版不能读取新数据库/新备份。备份包含确认保存的简历/JD 文本和场次快照，不含原始文件、登录状态、模型配置或密钥。

此次模型验证使用本机 HTTP 协议夹具，未发送真实简历、未使用用户 API Key，也未测评真实 DeepSeek/Ollama 的出题与评分质量。模型输出不合规范时明确失败并可重试；评分是练习反馈，不代表招聘结果。文档不支持扫描件 OCR、旧 `.doc` 或密码保护 PDF；限制为 10 MiB、30000 字符、200 页 PDF、DOCX 10000 条目/50 MiB 展开量及 30 秒解析时限。

## 实施取舍

继续使用已批准的 `feat/local-library` 工作区并保留本地分支；没有远程发布或合并。草稿采用即时本地 IPC 写入代替防抖，每次编辑产生一次轻量 SQLite 写入。岗位题库模式向模型提供最多 100 道随机且符合筛选的候选，界面已说明；超出候选池的题目不会参与该次优选。PDF 只执行文字提取，不调用脚本或渲染接口；pdfjs 6 已移除旧版 `isEvalSupported` 选项。候选题最多缓存 5 道，30 分钟后不可接受，下一次成功生成替换缓存；关闭页面不保存候选。
